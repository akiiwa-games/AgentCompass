# Security

## What AgentCompass reads on your machine

- **Provider sign-in files, read-only.** To find your accounts and read quota windows, AgentCompass reads the local sign-in state of the provider CLIs it routes to (Claude Code, Codex, Antigravity, Grok, Pi, and the homes of additional accounts). It does not refresh or overwrite the tokens of the Claude, Codex, Antigravity and Grok CLIs; refreshing stays with the owning CLI. One write exists: when the Codex usage endpoint answers 401 for the sign-in that Pi keeps in `~/.pi/agent/auth.json`, the Pi usage poll (`fetch_pi_usage` in `usage_core.py`) asks the provider for a new token and writes the new access and refresh token back to that file. Snapshots are bound to a one-way SHA-256 fingerprint of their credential source, not to the credential.
- **Never printed, logged or committed.** Credentials, tokens, raw transcripts and unredacted API responses are not written to output, logs, the decision ledger or the repository. A dollar API key found in a harness configuration is read again on each usage poll and is not copied into any AgentCompass file.
- **Local state** lives under `~/.agent-compass` (settings, usage cache, decision ledger, dispatch state). A scorer API key, if you configure one, is stored in `scorer-config.json` there.
- **Network.** Quota reads go to the providers you already use. Update checks read GitHub Releases. The reference data check reads the manifest `published/<schema>/public-data.json` and, when it changed, the files it lists from the repository's `main` branch on `raw.githubusercontent.com` (plain HTTPS GET, no credentials, only a fixed `User-Agent` and `Cache-Control` header; at most every 6 hours, `AGENTCOMPASS_PUBLIC_DATA=off` disables it). A fetched set is used only when every file matches the sha256 in the manifest and this version's own readers accept it; it never replaces your own settings.
- **What a publication can change.** A published reference set can change which model, effort and permission mode an install launches among the CLIs it already has, and how it ranks them; it cannot add a CLI, a provider or code. The trust is the repository's: the same account that publishes releases pushes `published/` to `main`. The sha256 in the manifest proves that the files are the ones the manifest lists, not who wrote them; both come from the same host.
  - *What is checked before a set is used*: every number is finite; each account's family and each bundle's harness is one this code launches (`account_fleet.LAUNCH_FAMILIES`, `LAUNCH_HARNESSES`); each bundle's effort is listed in the set's own `dispatch_efforts` table; every model id, effort, mode id, account and bundle id in the set matches a declared pattern (`launch_values.py`: no spaces, quotes, shell metacharacters or leading `-`); and this code's readers and two offline plans complete with it.
  - *What is not checked*: the `dispatch_efforts` table is itself published data, so a publication can list an effort a CLI does not accept (that CLI then refuses the launch); whether a model id exists at its provider; whether scores and prices are right.
  - *Values from your own machine* (account names you chose, model ids a provider lists) are not held to the patterns and never dropped: each is passed as its own command-line argument or quoted for the syntax it lands in, and a launch whose value cannot be expressed safely (a leading `-`, a line break) is refused by name. No launch passes a value through cmd.exe, which would read `&`, `|`, `>` or `%NAME%` in an argument as commands: a Windows batch launcher (an npm `.cmd` shim, Paseo's `paseo.cmd`) is read and started as the program its launch line runs, with the variables it sets (`launch_values.program`), and one that cannot be read that way refuses the launch, saying so.
  - *Classifier cases*: the text of `classifier-cases.json` enters the prompt of the System-One scorer, so a publication can steer how tasks are classified (and so routed); it cannot run anything.
  - *`api_family`*: for a proxy account you configured, a model row's `api_family` decides which CLI family receives your proxy address and key (`ANTHROPIC_*` for `claude`, `OPENAI_*` otherwise; `roll.provider_definition`). Only a family this code launches is used (membership in `roll.CLI_RUNS`), and the key goes only to the endpoint you configured.
- **Task text.** The task text is sent to the configured System-One scorer, which runs on your own subscription CLI or a configured API.

The reference for these rules is [`docs/technical-reference.md`](docs/technical-reference.md) (credential handling) and [`AGENTS.md`](AGENTS.md) (invariants).

## Reporting a vulnerability

Use GitHub's private vulnerability reporting: open the repository's **Security** tab, choose **Report a vulnerability**, or go to <https://github.com/akiiwa-games/AgentCompass/security/advisories/new>. Describe the affected version, what an attacker needs, and how to reproduce it. Please do not open a public issue for a vulnerability and do not include real credentials in a report.
